# Historical Run1 Stage 2 provenance

This folder preserves historical Run1 intermediate files (24 test reviews × 3 LLMs = 72 pairs). It is separate from the harmonized Stage 2 primary analysis used in the second revision. The unsuffixed Stage A′ snapshots in `05_test_data/` were overwritten by the August 2026 revision reruns and are not the Run1 files preserved here.

The source files listed in `MANIFEST.csv` are preserved copies. In 240 `snapshot_meta.json` files, the local absolute path prefix was removed so paths are relative to the repository root; the other listed files are byte-identical. The manifest records source paths, modification times, original SHA-256 (`sha256`), deposited SHA-256 (`sha256_deposited`), modification status and an explanatory `note`. Every selected source was last modified on or before 2026-05-11 (the two Elicit aggregate CSVs in `stage2_results/` on that date; all other sources earlier). This README and `CODEX_SCORE_FILE_SCOPE.csv` are explanatory annotations, not historical source files.

## Contents

- `queries/<domain>/<paper>/<model>/` holds one folder per stage:
  - `stage1/`: the query used as the Stage 2 input. For Claude Opus and ChatGPT Codex, and for 20 of the 24 Gemini Pro reviews, this is the reported Stage 1 query generated by the LLM. For the 4 Gemini Pro reviews with Phase 5 regeneration (41470797, 41715180, 41770755, 41804118), Run1 Stage 2 started from `with_laws_final`, the query after Phase 5 regeneration; this file is therefore not the reported Stage 1 query, which is in `05_test_data/<domain>/<paper>/model_outputs/gemini/with_laws_test_eval/normalized_query.txt`. These rows are marked in the `note` column of `MANIFEST.csv`.
  - `stageA_prime/`: the query after hit reduction to fewer than 9,999 records, including any Phase 5 regeneration. `snapshot_meta.json` records the hit count, the gate status and whether Phase 3 was attempted.
  - `stageA/`: the query after the exclusion-criteria NOT filters.
  - `stageB/`: the query after the metadata filters.
- `decision_logs/`: per-paper Stage A parse logs from the same run (exclusion criteria → NOT blocks).
- `stage2_results/`: per-stage hits and recall for Stage 1, A′, A, B and C for every pair, and the aggregate CSVs.
- `stageC_scores/`: historical deposited MedCPT article-level score files (63 pairs). Some Codex files contain only about 2,000 records from capped later executions; they are not complete candidate-set scores and do not establish reproduction of all reported Run1 aggregates.
  - `CODEX_SCORE_FILE_SCOPE.csv` labels all 24 Codex files. Eleven contain approximately 2,000 records despite a larger recorded Stage B input (nine exactly 2,000, one 1,999 and one 1,997). The index reports metadata counts, actual rows and file hashes. These later capped files do not determine the retention-rule counts or revised primary results; use `../stageC_harmonized/` for the latter.
  - The 9 Gemini Pro pairs not listed here had 1,000 or fewer records after Stage B. Under the passthrough rule they were not ranked.
- `phase5_prompts/`:
  - `gemini_original/`: the original Run1 Phase 5 regeneration prompts for the 4 Gemini Pro reviews.
  - `claude_reconstructed/`: the 6 Claude Opus Phase 5 prompts. The original files were overwritten by later runs, so these were rebuilt from the dated template and rulebook and are labelled as reconstructions.
  - ChatGPT Codex needed no Phase 5 regeneration.
  - No prompt contains gold-standard PMIDs or recall. In test mode the prompt builder omits that section.

## Reproduction note

`compute_24paper_aggregate_gate_floor.py` reads the Stage C file with `sorted(glob(...))[-1]`. In the working cache, files written by the August 2026 reruns can sort after the Run1 files. Use explicit historical input selection rather than the newest matching file. The preserved aggregate CSVs record the historical reported values; the deposited article-level files have the limitations described above and are not a guarantee of complete Run1 numerical reproduction.
