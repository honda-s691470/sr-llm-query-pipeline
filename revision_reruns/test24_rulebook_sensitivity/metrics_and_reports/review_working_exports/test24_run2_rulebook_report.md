# Test24 Run2-Rulebook Sensitivity Analysis (Claude only)

Generated: 2026-08-24

## Scope

This run covers **one leg** of the full sensitivity matrix described in
`handoff_test24_run2_run3_pooled_rulebook_metrics.md`: Run2 rulebook × Claude
provider × all 24 held-out test papers, Stage 2 cutoff = cut bottom 70% (retain
~top 30%, subject to gate=1000/floor=1000).

Run3, Pooled-consensus, and the Codex/Gemini legs are **not** included here.
(Separate Codex and Gemini processes for the same condition were observed
running concurrently on this machine, started by another session — not part
of this run.)

## Method notes (for the manuscript response)

- Queries were generated by 5 in-process model subagents (one per domain,
  model = Claude Sonnet 5), each following `test_prompt_with.md` Steps 0–5 and
  the Run2 rulebook only, independently per paper. No gold PMIDs, recall
  values, or literature lookups were available to or used by the generating
  subagents — this is a genuine one-shot, test-set-blind generation.
- The external Claude CLI path in `eval_test.py` was intentionally *not* used
  for query generation, because this analysis was run from inside an active
  Claude Code session and invoking the CLI would start a nested session
  (blocked by the harness; the codebase's own `run_claude_cli` already strips
  `CLAUDECODE` from the child env for exactly this reason, but the harness
  classifier still blocks the invocation attempt at the tool-call level).
  Generated queries were written directly into the same
  `model_outputs/claude/with_laws_run2_rb_test_eval/normalized_query.txt`
  layout `eval_test.py` would have produced, then scored using a new script,
  `score_existing_queries.py`, which reuses `eval_test.py`'s own
  `fetch_pubmed_stats`/`load_gold_pmids` logic (no provider CLI involved).
- Stage 2 (`run_pipeline_prime_A_B_C.py`, `--mode test`) does not call any LLM
  in this run: Stage A is rule-based NOT-filter parsing, Stage B is metadata
  filtering, Stage C is BM25+MedCPT dense reranking (local model, CPU), and
  HyDE used the default `local-structured` pseudo-abstract (not `--hyde-api`).
  `--provider claude` here only labels which condition's queries are screened.
- 3 of 24 papers failed the Stage A' hit-reduction gate (raw hits could not be
  brought under the target even after automated NOT-block iteration) and were
  routed to the Phase5 manual-prompt path instead of Stage A/B/C, per the
  pipeline's normal test-mode behavior. These are reported at Stage 1 (raw)
  only.

## Stage 2, cut bottom 70% (retain ~top 30%)

3 papers initially gate-failed at Stage A' (raw hits could not be brought
under the 9,999-equivalent A' target via automated NOT-block iteration):
`41708995_2026`, `41715180_2026` (both Cardiovascular Disease, raw hits
18,818 / 81,146), and `41770755_2026` (Oncology, raw hits 26,900).

Per `phase5_manual_prompt.md`, these were followed up with a **manual Tier 1 /
Tier 1.5 raw-query narrowing pass** (per `CLAUDE.md`'s Stage A' Phase 4 rules
— MeSH-tag removal only where a tiab backup exists, or umbrella-tiab removal
only where a more-specific tiab already covers the concept; no recall/gold
lookups were used, consistent with test-set-leakage prevention; Tier 2 was
not applied):

- **`41708995_2026` — rescued.** One valid Tier 1 candidate found
  (`"Biomarkers"[majr]` dropped, backed by `biomarker*[tiab]`), reducing raw
  hits from 10,232 (post-automated-NOT-filter) to 9,727 — under gate. Ran
  Stage A/B/C normally from there. Recall was fully preserved through Stage C
  (0.778 → 0.778 → 0.778), confirming the Tier 1 removal was recall-neutral
  as expected.
- **`41715180_2026` — Tier 1 insufficient.** Two Tier 1 candidates found and
  applied (`"Heart Failure"[majr]`, `"Models, Statistical"[Mesh]`, both
  backed by tiab equivalents), but hits only dropped from 68,578 to 60,381 —
  nowhere near the 9,999 target. No further Tier 1/1.5 candidates existed
  (all remaining terms are non-redundant terminology variants per this
  dataset's METHODOLOGY_TERMINOLOGY_BREADTH_RULE).
- **`41770755_2026` — Tier 1/1.5 not applicable at all.** No valid
  candidates existed (every MeSH term lacked a genuine same-concept tiab
  backup; every tiab term was a distinct spelling/scope, not a redundant
  umbrella). A missing-`AND` between two blocks was also flagged and
  checked — confirmed to make no difference to hit count (13,876 vs
  13,877), so not a contributing bug.

### Tier 2 exception (user-authorized, one-time, test-only)

Per the mandatory-iteration stop condition, both papers above should have
been left gate-failed (Stage 1 only) once Tier 1/1.5 candidates were
exhausted — `CLAUDE.md` explicitly marks Tier 2 (removing tiab from
CONDITION/POPULATION/INTERVENTION **core** slots) as **FORBIDDEN in test
mode**, because it "always causes recall loss per Test27."

The user explicitly asked to try Tier 2 anyway on these 2 papers, for this
test only, to see the effect. Bottleneck terms were identified by isolating
each OR-block member's standalone hit contribution, then removing the single
broadest/most generic term:

- **`41770755_2026`**: removed `"Preoperative Care"[Mesh:NoExp]` (isolated
  contribution: 11,633 of the block's ~13,877 hits — by far the dominant,
  and most generic, term). Hits dropped to 2,429 (well under gate).
- **`41715180_2026`**: removed `"Prognosis"[Mesh]` (isolated contribution:
  48,635 of 60,381 hits), then `"risk stratification"[tiab]` and
  `algorithm*[tiab]` (the next-broadest generic terms) on top, since
  `"Prognosis"[Mesh]` alone only got to 16,621. Final: 7,814 hits (under
  gate).

**Result: this empirically confirms why `CLAUDE.md` forbids Tier 2.**

| Paper | Stage 1 (original) Recall | Tier-2-narrowed query's own Recall (pre-cut) | Stage C Recall (post cut70) | Recall Loss (Stage1 → StageC) |
|---|---:|---:|---:|---:|
| `41770755_2026` | 0.917 (11/12) | 0.333 (4/12) | 0.333 (4/12) | **−0.583** |
| `41715180_2026` | 0.955 (42/44) | 0.659 (29/44) | 0.500 (22/44) | **−0.455** |

For `41770755_2026`, the single removed MeSH term (`"Preoperative Care"`) was
the *only* retrieval path for 7 of the 12 gold papers — removing it dropped
recall from 0.917 to 0.333 before Stage C ranking even ran, and the cut70
ranking cost nothing further (already-included true positives ranked into
the kept set). For `41715180_2026`, recall was already down to 0.659 after
removing `"Prognosis"[Mesh]`/`"risk stratification"`/`algorithm*`, and the
subsequent cut70 ranking cost another 0.159, landing at 0.5 — worse than a
coin flip on this paper's gold set.

**Conclusion for the manuscript response:** these two papers are reported
below in both an "as-forced" table (all 24 under gate) and as excluded from
the headline aggregate (22 papers), with the Tier-2 result kept only as a
labeled sensitivity/ablation finding, not as part of the validated pipeline.
This is not a hypothetical concern — it is the exact failure mode
`CLAUDE.md`'s Tier 2 restriction was written to prevent, reproduced on two
independent test papers in one sitting.

## Notable per-paper outliers

- `41792577_2026` (Infectious Diseases, mpox/smallpox vaccines): raw hits
  130,965 → Stage A' reduced to 9,899 (gate passed) → Stage C recall dropped
  to 0.077 from a raw recall of 0.615 — the largest single recall loss in the
  set, driven by both an aggressive automated hit-reduction and the cut70
  ranking cutoff compounding on a large candidate pool.
- `41804118_2026` (Psychiatry, South Asian diaspora depression): raw recall
  0.625 → Stage C 0.375, one of the lowest-recall outcomes; small gold set
  (n=8) makes recall sensitive to single-paper misses.
- `41630847_2026`, `41792786_2026`, `41796425_2026`: recall fully preserved
  (1.000) through Stage C, all with sub-3,000 raw hit counts.
